# Evaluation Scope and Integrity Notes

**Scope of this snapshot:** demo-tier feasibility study on a controlled synthetic
fixture. The thesis-tier protocol in `ground_truth/PRE_REGISTRATION.md` is a
plan, not a delivered result.

## What is actually measured

| Metric | Current result | What it measures | What it does not measure |
|---|---:|---|---|
| M1 feature recall | 8/8 | Capability + at least one locator-supported gold anchor | Open-world recall on an unseen estate |
| M2 feature precision | 8/8 | Emitted features matched to gold capabilities/anchors; duplicates penalised | Precision against an independent annotator's feature inventory |
| M3 evidence support | 101/101 all links; 30/30 stratified sample | Path containment, excerpt SHA, non-placeholder text, line/XPath support | Semantic entailment; a true-but-irrelevant excerpt can pass |
| M4 disposition correctness | 12/12 | Static mapping rule pack vs frozen gold rows, snapshot-grounded | A learned or independently authored disposition method |
| M5 estimate-moving issue recall | 6/6; 6/8 fixed allowance | Planted issues matched by anchored rule/path signals | A ranked issue list, severity model, or estimate regression |
| M6 finding micro-F1 | 48/48 (24 TP / 0 FP / 0 FN) | 8 rules x 3 positives + 3 hard negatives; every finding link audited; unlabelled paths and extra rules count as FP | Line-level matching or real-estate false-positive rates |
| Holdout capability recall | 4/4 | Capability names under a naming-shift fixture; pre-computed and not imported | Precision, anchors, a second LOB, or generalisation |
| Reference macro-F1 | 1.00 | Disposition classes vs an internally authored reference target | Independent target authorship; target values are now compared |

## Integrity changes in this build

- M1/M2 anchors require locator-supported evidence, not just a path.
- M3 audits all discovery links; an invalid XPath fails rather than falling back
  to a line match. Path escape and placeholder excerpts fail.
- M4 mappings must be grounded in snapshot evidence or manifest paths.
- M5 signals require the expected anchored path/source, not only a rule ID.
- M6 requires every evidence link on a finding to be supported; unlabelled
  paths and findings from rules outside the gold set count as false positives.
- The `UNLABELLED` per-rule row is shown when an extra rule fires.
- The packet hash covers rendered HTML; `packet_json` covers canonical JSON;
  content digests bind findings/mappings/evidence; `verify-packet` checks all
  three and `verify-audit` checks the chain only.
- `annotation_concordance.json` records an aggregate AI-assisted pass, not human
  inter-annotator agreement; no item-level labels or adjudication log are
  published. Do not present kappa as human reliability.

## Known residual limitations

1. The feature/mapping/review rule packs encode fixture-specific names and the
   gold files were generated by the same fixture build. This is a rule-pack
   consistency test, not an independent evaluation.
2. There is one synthetic 300-file LOB/feature slice. The 650-file estate is a
   filler-heavy variant, not a second LOB.
3. The reference target is internally authored and AI-assisted.
4. No real anonymised estate, blind SME annotation, or reviewer-time study has
   been run.
5. The Cloud API extension draft is a local JSON contract, not Guidewire
   schema/updater syntax, and has not been compiled or tenant-validated.
6. The holdout is four features, naming-shift only, and capability-only in the
   pre-computed aggregate.
7. The product pipeline reads frozen gold to produce evaluation metrics; it does
   not use gold to drive feature discovery or reconstruction.

## What would make the next tier credible

- Independent blind annotation by 2-3 Guidewire SMEs with item-level labels,
  adjudication, and kappa with a confidence interval.
- A second LOB and a real anonymised estate, with parser coverage measured.
- An actual ranked M5 output and a reviewer-time / estimate-variance endpoint.
- Compile or tenant validation of one extension draft.
- A baseline against the SI's existing CUE/Cloud Assurance spreadsheet workflow.
